# GodDB 기능 명세 (Windows)

> GodDB for Windows 1.3.7 (macOS 판 1.3.7 과 같은 기능) · 대상 DB: MySQL 5.7 / 8.x (AWS RDS 포함), PostgreSQL 12+, SQL Server 2016+, Redis 6+
> 운영체제: Windows 10 1809 이상 / Windows 11, x64. .NET 은 앱에 들어 있어 따로 설치하지 않아도 된다.
> macOS 판 GodDB 와 같은 기능을 Windows 에 맞게 옮긴 앱이다. 이 문서는 앱 안의 AI 어시스턴트(사용법 질문)와 **새로운 기능** 창이 읽고, 기능이 추가·변경될 때마다 함께 갱신한다.

## 0. 지원 DB 와 DB 별 차이

| 항목 | MySQL | PostgreSQL | SQL Server |
|---|---|---|---|
| 드라이버 | MySqlConnector | Npgsql (결과를 텍스트 형식으로 받음) | Microsoft.Data.SqlClient |
| 인증 | 사용자 / 비밀번호 | 사용자 / 비밀번호 | **SQL 인증** (사용자 / 비밀번호) 또는 **Windows 인증** (통합 인증) |
| 기본 포트 | 3306 | 5432 | 1433 (명명된 인스턴스 `host\instance` 는 포트를 쓰지 않음) |
| 사이드바 드롭다운 | DB | **스키마** (접속 DB 는 접속 설정에서 지정) | DB |
| 테이블 이름 | `table` | `table` (선택한 스키마 안) | dbo 는 `table`, 그 외 `schema.table` |
| 식별자 인용 | `` `x` `` | `"x"` | `[x]` |
| 자동 행 제한 | `LIMIT n` | `LIMIT n` | `SELECT TOP n` |
| 읽기전용 | 앱 검사 + `SET SESSION TRANSACTION READ ONLY` | 앱 검사 + `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY` | **앱 검사만** (세션 설정 없음) |
| CREATE 문 보기 | 서버의 `SHOW CREATE TABLE` | 메타데이터로 생성 (CREATE TABLE + INDEX + COMMENT) | 메타데이터로 생성 (+ MS_Description) |
| 실행 계획 | `EXPLAIN` + `FORMAT=TREE` | `EXPLAIN` (QUERY PLAN 트리) | `SET SHOWPLAN_ALL ON` |
| 주의사항 분석 | type=ALL, filesort, temporary | Seq Scan, 디스크 정렬, 큰 Nested Loop | Table/Clustered Index Scan, Sort, Key Lookup |
| 인덱스 상세 | `SHOW INDEX` | pg_indexes + 사용 횟수/크기 | `sp_helpindex` |
| 프로시저 호출 틀 | `CALL p();` | `CALL p();` | `EXEC p;` |
| 기본값 입력 (ALTER) | 값 그대로 (`A` → `'A'`) | **SQL 식** (`'A'`, `now()`) | **SQL 식** (`('A')`, `(getdate())`) |
| 컬럼 위치 (AFTER) | 지원 | 미지원 (항상 맨 뒤) | 미지원 (항상 맨 뒤) |
| 코멘트 | `COMMENT` | `COMMENT ON` | 확장 속성 `MS_Description` |
| 스크립트 구분자 | `DELIMITER` | — | `GO` |

- 한 번에 여러 문장 실행: PostgreSQL 은 스크립트를 문장 단위로 나눠 차례로 실행한다 (`$$ … $$` 함수 본문은 나누지 않음). SQL Server 는 배치로 한 번에 보낸다 (`GO` 가 있으면 그 단위로 나눔).
- MySQL 에서 결과 집합을 돌려주는 프로시저(`CALL p(…)`)는 결과를 표로 보여준다 (결과 집합이 여러 개면 첫 번째).
- 오류 번역: PostgreSQL SQLSTATE(28P01, 3D000, 42P01, 42703, 42601, 42501, 25006…), SQL Server 번호(18456, 4060, 208, 207, 102, 229…)에 한국어 해결 방법을 붙인다.
- 비밀번호 오류 재입력: MySQL 1045 / PostgreSQL 28P01 / SQL Server 18456 (SQL 인증일 때).

### SQL Server Windows 인증
- 접속 편집에서 DB 종류가 SQL Server 이면 **인증: SQL 인증 / Windows 인증** 을 고른다.
- **Windows 인증**이면 사용자 · 비밀번호 칸이 숨겨지고, 지금 Windows 에 로그인한 계정으로 접속한다 (통합 인증, `Integrated Security`). 비밀번호를 묻거나 저장하지 않는다.
- 도메인 환경에서는 서버 이름으로 Kerberos 인증을 하므로 호스트 칸에 IP 보다 **서버 이름**을 쓰는 것이 좋다.
- 명명된 인스턴스: 호스트 칸에 `host\instance` (예: `db01.example.com\SQLEXPRESS`) 로 쓰면 SQL Server Browser 로 포트를 찾는다 (포트 칸은 쓰지 않음).

## 1. 화면 구성

```
┌───────────────┬──────────────────────────────────────────────┐
│ 메뉴 막대: 파일 · 편집 · 데이터베이스 · 보기 · 도움말                │
├───────────────┬──────────────────────────────────────────────┤
│ 사이드바        │ [쿼리 | 스키마 비교 | 모델링]                   │
│ - 접속 목록     │ 탭 바                                         │
│ - DB 선택       │ SQL 편집기                                    │
│ - 테이블        │ ─────── (드래그로 높이 조절)                    │
│   - 컬럼        │ 결과 표                    │ 행 상세 (선택 시)  │
│   - 인덱스      │                                              │
│ - 뷰/프로시저…  ├──────────────────────────────────────────────┤
│ - 테이블 검색   │ 상태창 (Ctrl+Shift+L, 드래그로 높이 조절)        │
│               │ 상태 표시줄: 마지막 이벤트 · 오류 수 · [상태창]   │
└───────────────┴──────────────────────────────────────────────┘
```

- 메뉴는 창 안의 메뉴 막대에 있다: **파일**(새 쿼리 탭 · 새 접속 · 탭 닫기 · SQL 파일 · 설정 · 끝내기), **편집**, **데이터베이스**(스키마 새로고침 · 접속 끊기 · 객체 빠른 찾기 · 쿼리 히스토리), **보기**(쿼리 / 스키마 비교 / 모델링, 상태창, AI 어시스턴트, 레이아웃 초기화), **도움말**(새로운 기능 · 문제 보고 · 업데이트 확인).
- 사이드바와 본문 사이 경계는 드래그로 너비를 조절한다 (200 ~ 520).
- 편집기/결과, 결과/행 상세, 본문/상태창 경계도 모두 드래그로 조절한다.
- 오른쪽에 **AI 어시스턴트** 패널을 열 수 있다 ([28](#28-ai-어시스턴트-오른쪽-패널)).

## 2. 접속 관리

| 항목 | 설명 |
|---|---|
| DB 종류 | MySQL / PostgreSQL / SQL Server / Redis. 바꾸면 포트가 기본값으로 바뀐다 (직접 바꾼 포트는 유지) |
| 이름 | 사이드바에 보이는 이름 (앞에 DB 로고 표시) |
| 인증 (SQL Server) | SQL 인증 / Windows 인증 ([0](#0-지원-db-와-db-별-차이)) |
| 호스트 / 포트 | `localhost` 를 쓰면 IPv4(127.0.0.1) → IPv6(::1) 순서로 모두 시도한다. SQL Server 는 `host\instance` 도 된다 |
| 사용자 / 기본 DB | 기본 DB 를 비우면 접속 후 첫 번째 DB 를 연다 |
| TLS 사용 | 켜면 암호화 연결. 인증서 검증은 하지 않는다 (터널 경유 시 호스트명이 달라지기 때문) |
| 접속 환경 | 없음 / 개발 / 스테이징 / 운영. 사이드바·탭에 색으로 표시. **운영** 접속은 데이터를 바꾸는 문장을 실행하기 전에 항상 확인한다 |
| 그룹 | [29. 접속 그룹](#29-접속-그룹) |
| 읽기전용 | [5. 읽기전용 모드](#5-읽기전용-모드) |
| 비밀번호 저장 | [3. 비밀번호 저장](#3-비밀번호-저장) |
| SSH 터널 | [4. SSH 터널](#4-ssh-터널) |

- **여러 접속을 동시에 열 수 있다.** 사이드바에서 접속을 누르면 다른 접속은 끊지 않고 연결(이미 연결돼 있으면 보기만 전환)한다.
  - **더블클릭** → 연결한 뒤 그 접속의 쿼리 탭으로 이동, 탭이 없으면 새 쿼리 탭 (스키마 비교 · 모델링 화면이면 쿼리 화면으로).
  - 접속 줄: [연결 상태] [DB 아이콘] 이름 [환경]. DB 아이콘은 각 DB 의 로고를 브랜드 색으로 (MySQL 돌고래, PostgreSQL 코끼리, Redis — Simple Icons, CC0). SQL Server 는 공식 로고를 쓸 수 없어 빨간 서버 아이콘. 마우스를 올리면 DB 이름. 보고 있는 접속은 이름이 굵게.
  - 접속 왼쪽 점: 초록 = 연결됨, 빨강 = 실패, 회색 = 안 됨. 오른쪽 숫자 = 그 접속의 쿼리 탭 수.
  - 우클릭 → 새 쿼리 탭 / 다시 연결 / 연결 끊기 (연결 안 됐으면 연결) / 편집 / 복제 / 그룹으로 이동 / 삭제 (삭제는 확인).
  - 메뉴 **데이터베이스** → 보고 있는 접속 끊기, 모든 접속 끊기.
  - 툴바에 보고 있는 접속과 "열린 접속 N개" 표시.
- 접속을 끊어도 그 접속의 쿼리 탭은 남는다. 다시 연결하면 이어서 쓸 수 있다.
- 트랜잭션이 열린 접속을 편집하거나 다시 연결하면 먼저 커밋/롤백을 묻는다.
- **연결 테스트**: 저장하지 않고 연결해 DB 버전을 보여준다. 결과는 상태창에도 남는다.

## 3. 비밀번호 저장

| 설정 | 동작 |
|---|---|
| 비밀번호 저장 켬 (기본) | **Windows 자격 증명 관리자**에 저장 (대상 `GodDB:<접속 ID>`, 일반 자격 증명, 이 PC 에만). 다음부터 묻지 않는다 |
| 비밀번호 저장 끔 | 연결할 때마다 입력창이 뜬다. 입력한 값은 **앱을 끌 때까지만** 메모리에 기억한다 |

- 저장된 비밀번호는 지금 Windows 사용자 계정에 묶여 있다. **제어판 > 자격 증명 관리자 > Windows 자격 증명** 에서 `GodDB:` 로 시작하는 항목으로 보이고, 거기서 지울 수도 있다.
- 접속 편집 화면에 "자격 증명 관리자에 저장된 비밀번호가 있어요" 표시와 **저장된 비밀번호 지우기** 버튼이 있다.
- 비밀번호가 틀리면 (MySQL 1045 / PostgreSQL 28P01 / SQL Server 18456) 바로 비밀번호 입력창이 다시 뜬다.
- 입력창에서도 "자격 증명 관리자에 저장" 여부를 고를 수 있다.
- 비밀번호 저장으로 설정했지만 자격 증명 관리자에 없거나 읽지 못하면, 비밀번호 없이 연결하지 않고 입력창을 띄운다.
- 비밀번호 · 암호 칸 오른쪽 **눈 버튼**으로 입력한 값을 보이기 / 가리기.
  - 저장된 비밀번호를 볼 때는 매번 **Windows 본인 확인**을 거친다: **Windows Hello**(지문 · 얼굴 · PIN)가 설정돼 있으면 Hello 로, 없으면 Windows 자격 증명 입력창에 **Windows 로그인 암호**를 넣어 확인한다.
  - 칸을 완전히 비우고 새로 입력한 값은 확인 없이 보인다. 한 글자만 지운 값은 저장된 비밀번호로 보고 확인을 거친다.
  - 저장된 비밀번호를 보면 상태창 · 로그 · 감사 로그에 "저장된 비밀번호 보기"가 남는다 (값은 남기지 않음).
- SQL Server **Windows 인증** 접속은 비밀번호가 없으므로 저장하지 않는다.
- 비밀번호는 `profiles.json` 에 절대 기록하지 않는다.

## 4. SSH 터널

- Windows 에 들어 있는 OpenSSH 의 `ssh.exe -N -L 127.0.0.1:<빈 포트>:<DB 호스트>:<DB 포트>` 로 터널을 연다.
  - 먼저 `C:\Windows\System32\OpenSSH\ssh.exe` 를 쓰고, 없으면 PATH 에 있는 `ssh.exe` 를 쓴다.
  - ssh 를 찾지 못하면 **OpenSSH 클라이언트** 설치를 안내한다: Windows 10 은 **설정 > 앱 > 선택적 기능**, Windows 11 은 **설정 > 시스템 > 선택적 기능** 에서 "기능 추가" → "OpenSSH 클라이언트". (Windows 10 1809 이후 대부분 기본으로 설치돼 있다)
- `%USERPROFILE%\.ssh\config`, `known_hosts`, **ssh-agent** 를 그대로 쓴다. 키 파일을 비우면 agent/설정 파일을 따른다.
  - ssh-agent 를 쓰려면 Windows 서비스 **OpenSSH Authentication Agent** 를 켜고 `ssh-add` 로 키를 넣는다.
- 옵션: `BatchMode=yes`(비밀번호 묻지 않음), `StrictHostKeyChecking=accept-new`, `ExitOnForwardFailure=yes`, `ServerAliveInterval=30`.
- 15초 안에 포트가 열리지 않거나 ssh 가 종료되면 ssh 의 오류 메시지를 그대로 보여준다.
- 키 파일은 **본인 계정만 읽을 수 있어야** 한다 (Windows OpenSSH 는 다른 사용자가 읽을 수 있는 키를 거부한다). 파일 속성 > 보안에서 본인 계정 외의 권한을 지운다 (Mac/Linux 의 `chmod 600` 에 해당).
- 지원: 키 파일 인증 / ssh-agent. **미지원: 비밀번호 방식 SSH.**

## 5. 읽기전용 모드

두 단계로 막는다.

1. **앱 검사**: 첫 키워드가 `SELECT / SHOW / DESC / DESCRIBE / EXPLAIN / USE / WITH` 일 때만 실행.
   - `INTO OUTFILE / DUMPFILE` 포함 시 차단, `WITH … UPDATE/DELETE…` 차단.
2. **서버 설정**: 연결 직후 `SET SESSION TRANSACTION READ ONLY` (PostgreSQL 은 `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY`) → 앱 검사를 우회해도 서버가 DML 을 거부 (MySQL 오류 1792). SQL Server 는 세션 설정이 없어 앱 검사만 한다.

- 사이드바와 툴바에 빨간 **읽기전용** 표시.
- 테이블 수정(ALTER) 화면의 실행 버튼, 결과 편집, 테이블 이름 변경 · 삭제, CSV 가져오기가 꺼진다.
- 자동 커밋 체크박스가 없다.

## 6. 스키마 브라우저

- 사이드바 상단 드롭다운으로 DB 를 바꾼다 (`information_schema`, `mysql`, `performance_schema`, `sys` 는 숨김).
- 테이블을 펼치면 컬럼(🔑 PK, 타입, NN)과 **인덱스 폴더**가 보인다.
- 테이블 더블클릭 → `SELECT * … LIMIT 500` 실행.
- 테이블 우클릭 메뉴

### CSV 가져오기
- 테이블 우클릭 > **CSV 가져오기…** → 파일 선택 → 미리 보기, CSV 컬럼과 테이블 컬럼 맞추기 → **한 트랜잭션**으로 INSERT (하나라도 실패하면 전부 되돌림).
- 파일 인코딩: BOM 이 있으면 그 인코딩, 없으면 UTF-8 로 읽고, **UTF-8 이 아니면 CP949(한글 Windows 기본, 엑셀 "CSV" 저장 형식)** 로 읽는다.

## 7. 쿼리 편집기

- **쿼리 탭은 탭마다 접속 / DB(스키마)가 정해져 있다.** 탭에 `[DB 로고] 쿼리 N` 과 `접속명 / DB` 가 표시된다.
  - `+` 또는 `Ctrl+T` → **사이드바에서 보고 있는 접속 / DB** 로 새 탭. 다른 접속을 누르고 `+` 하면 그 접속의 탭이 생긴다.
  - 탭을 고르면 사이드바도 그 탭의 접속 / DB 로 바뀐다. 사이드바에서 DB 를 바꾸면 보고 있는 탭의 DB 도 바뀐다.
  - 같은 접속의 탭끼리 DB 가 달라도 된다. 실행 직전에 탭의 DB 로 맞춘다 (`USE` / `search_path`).
  - 처음에는 탭이 없다. 접속을 처음 연결하면 그 접속의 탭이 하나 열린다.
  - 연결이 끊긴 접속의 탭은 회색 점으로 표시되고, 실행하면 다시 연결하라고 안내한다.
  - 탭 우클릭 → 이 접속에 새 탭 / 탭 닫기 / 다른 탭 모두 닫기. `Ctrl+W` 는 보고 있는 쿼리 탭을 닫는다 (창은 닫지 않음).
  - **탭 자동 저장**: 열린 쿼리 탭과 편집 중인 SQL 은 앱을 껐다 켜도 남는다.
- 끌어서 바꾼 화면 경계 크기는 기억해서 모든 탭 · 다음 실행에 쓴다: 편집기 / 결과 높이, 행 상세 폭, 상태창 높이 · 로그 상세 폭, AI 어시스턴트 폭, ER 다이어그램 AI 패널 폭, 모델링 목록 폭 · 아래 편집기 높이, Redis Workbench 높이.
  - 메뉴 **보기 > 레이아웃 초기화** 로 모두 처음 크기로 되돌린다.
- 좁은 창(AI 어시스턴트를 연 경우 등)에서는 도구 막대의 "페이지" 이름표와 단축키 안내를 숨기고, 페이지 크기 선택(500 등)은 줄이지 않고 항상 보인다. 결과 아래 줄(행 범위 · 페이지 이동 · 실행 시간 · 전체 행 수 · 내보내기)은 줄바꿈 없이 한 줄.
- 키워드·문자열·숫자·백틱 식별자·주석 하이라이트.
- **주석 토글** (`Ctrl+/`): 선택한 줄(또는 커서 줄)을 `-- ` 주석으로 넣고 빼기. **SQL 정렬** (`Ctrl+Alt+L`): 키워드 줄바꿈 · 들여쓰기로 보기 좋게. `Ctrl+Enter` 로 실행될 문장을 강조한다.
- **실행 대상**
  - `Ctrl+Enter` / ▶ 실행: 선택 영역이 있으면 → **선택한 부분만** 실행 (선택 안에 문장이 여러 개면 그 문장들을 차례로). 선택이 없으면 → **커서가 있는 문장 하나만** (편집기에서 강조된 문장)
  - `Ctrl+Alt+Enter` / ⏩ 전체 실행: **편집기의 모든 문장을 위에서부터 차례로** 실행
  - 문장 구분은 세미콜론 기준 (따옴표·주석·PostgreSQL `$$ … $$` 안의 `;` 는 무시). MySQL `DELIMITER`, SQL Server `GO` 구분자도 이해한다.
  - 중간 문장이 실패하면 그 자리에서 멈추고 "N번째 문장에서 멈췄어요 (앞의 N-1개는 실행됨)" 를 보여준다. 앞 문장 결과는 그대로 볼 수 있다.
  - **안전장치**: 전체 실행하는데 변경 문(INSERT/UPDATE/DELETE/DDL 등)이 섞여 있으면 실행 전에 확인창을 띄운다 (변경 문 미리보기 포함). 조회 문만 있으면 바로 실행.
  - **위험한 명령 확인**: WHERE 없는 DELETE / UPDATE, TRUNCATE, DROP (Redis 는 FLUSHALL · FLUSHDB · KEYS 등) 은 한 문장이어도 실행 전에 확인한다. **설정 > 일반 > 안전 > 위험한 명령 실행 전 확인** 으로 끌 수 있다 (기본 켬, 켜고 끈 기록은 감사 로그에 남음). 운영 접속에서 데이터를 바꾸는 확인은 이 설정과 관계없이 항상 뜬다.
- **쿼리 취소**: 실행 중 **[취소]** 버튼 또는 `Ctrl+.` (MySQL · PostgreSQL · SQL Server). 취소하면 결과 대신 "쿼리를 취소했어요" 로 표시. 설정 > 일반 > 쿼리 > **실행 시간 제한**을 넘기면 자동으로 취소한다.
- **결과 탭**: 여러 문장을 실행하면 결과 영역 위에 `1 SELECT 3행 · 2 UPDATE 실행 완료 …` 형태의 탭이 생긴다. 기본으로 결과 표가 있는 마지막 결과를 보여준다.
- **실행 계획** (`Ctrl+Shift+Enter`)은 선택 영역 또는 커서가 있는 문장 하나만 대상으로 한다.
- **LIMIT 자동 부여**: LIMIT 이 없는 SELECT 에만 붙인다 (100 / 500 / 1000 / 5000 / 제한 없음). `FOR UPDATE`, `INTO` 가 있으면 붙이지 않는다.
- **쿼리 히스토리** (`Ctrl+Y`, 데이터베이스 > 쿼리 히스토리…): 실행한 SQL 을 검색하고 편집기에 다시 넣는다.
- **.sql 파일**: 파일 > SQL 파일 열기…(`Ctrl+Shift+O`) · 저장(`Ctrl+S`) · 다른 이름으로 저장…(`Ctrl+Shift+S`) · 최근 SQL 파일, 탐색기에서 `.sql` 파일을 창에 끌어 놓아도 열린다. 저장에 실패하면 알려준다.

### Tab 자동완성

| 상황 | 후보 |
|---|---|
| `m.` / `m.em` (별칭 또는 테이블명 뒤 점) | 그 테이블의 컬럼만 (컬럼 순서대로) |
| `FROM` / `JOIN` / `UPDATE` / `INTO` / `TABLE` / `DESC` 바로 뒤 | 테이블, 뷰 우선 |
| 그 외 | 구문에 나온 테이블의 컬럼 → 키워드·함수 → 테이블 → 뷰/프로시저/함수 |

- 별칭 해석: `FROM tb_member m`, `JOIN tb_order AS o`, `FROM a x, b y`, `shop.tb_member` 형식 지원. `WHERE`/`ON` 등은 별칭으로 보지 않는다.
- 동작
  - 후보 1개 → 바로 채움
  - 후보 여러 개인데 공통 앞부분이 더 길면 → 공통 부분까지 채움 (한 번 더 Tab 하면 목록)
  - 그 외 → 자동완성 목록 (↑↓ 선택, Enter 확정, Esc 취소)
  - 커서 앞이 공백이면 → 공백 4칸 (들여쓰기)
- 키워드 대소문자: 소문자로 입력하면 소문자 키워드(`sel` → `select`), 대문자면 대문자.
- 후보는 현재 선택된 DB 의 스키마 기준 (최대 50개).

- **결과 행 수 "제한 없음"**: 보이지 않게 1,000행씩 나눠 받고, 표를 끝까지 스크롤하면 다음 행을 이어 붙인다 (화면 최대 200,000행 — 넘으면 안내, 전체는 [내보내기]).
- **큰 값 보호**: 한 칸이 100만 자를 넘으면 표에는 앞부분만 담고(편집 막음), 내보내기는 전체를 저장한다. Redis 문자열은 1MB 넘으면 앞 1MB 만 보여주고 편집을 막는다.
- **트랜잭션 (자동 커밋 / 수동 커밋)** — 쿼리 도구 막대의 **자동 커밋** 체크박스 (접속 단위, 연결할 때마다 켜짐, Redis·읽기전용 접속에는 없음)
  - 끄면 INSERT · UPDATE · DELETE 같은 쓰기 문장을 실행할 때 트랜잭션을 열고, **[커밋]** 해야 DB 에 반영된다. 조회만 하면 트랜잭션을 열지 않는다.
  - 열려 있는 동안 주황색 `트랜잭션 · 변경 N건` + **[커밋] [롤백]**. 롤백하면 열린 결과를 다시 읽는다.
  - 결과 표 편집 적용도 열린 트랜잭션에 합류한다 (따로 커밋하지 않음).
  - 편집기에 직접 `COMMIT` / `ROLLBACK` / `BEGIN` 을 써도 상태가 맞춰진다. **MySQL 은 CREATE · ALTER · DROP 이 자동 커밋**된다.
  - 열린 트랜잭션이 있는데 자동 커밋을 켜거나 연결을 끊으면 커밋/롤백을 묻는다. 앱을 끄면 "롤백하고 종료" 를 묻는다.
  - 감사 로그: 자동 커밋 켬/끔(설정), 커밋 · 롤백(실행, 변경 건수).

## 8. 결과 표와 행 상세

- 결과 표의 행을 클릭하면 오른쪽에 **행 상세** 패널이 열린다.
  - 모든 컬럼의 **전체 값**을 줄바꿈 그대로 보여준다 (텍스트 선택 가능).
  - 컬럼별 글자 수, 값 복사 버튼.
  - 패널 너비는 경계를 드래그해 조절.
- 결과가 1행이면 (예: `SHOW CREATE …`) 상세 패널이 자동으로 열린다.

### 페이징 (500행 단위)
- SELECT 결과는 **페이지 크기(기본 500행) 단위**로 가져온다. 툴바 "페이지" 에서 100 / 500 / 1000 / 5000 / 제한 없음.
- 결과 아래: `⏮ ◀ 501–1,000행 ▶ ⏭` · "2페이지 · 더 있음/끝" · **전체 행 수** 버튼.
  - 다음 페이지가 있는지는 페이지 크기 + 1 행을 요청해서 알아낸다.
  - **전체 행 수**는 `SELECT COUNT(*) FROM (원래 쿼리)` 로 센다 (버튼을 눌렀을 때만, 큰 테이블은 오래 걸릴 수 있음). 세고 나면 "전체 N행 · 3/12페이지" 와 마지막 페이지 버튼이 보인다.
  - 페이지를 넘길 때마다 같은 쿼리를 OFFSET 만 바꿔 다시 실행한다 (그사이 데이터가 바뀌면 경계가 어긋날 수 있음 — DataGrip 과 같은 방식).
- DB 별: MySQL·PostgreSQL `LIMIT n+1 OFFSET m` / SQL Server 는 맨 바깥 ORDER BY 가 있으면 `OFFSET m ROWS FETCH NEXT n+1 ROWS ONLY`, 없으면 `TOP (m+n+1)` 로 가져와 앞부분을 버린다.
- 이미 `LIMIT / TOP / OFFSET / FETCH / INTO / FOR UPDATE` 가 있는 쿼리, SELECT 가 아닌 문장은 그대로 실행한다 (페이징 없음).
- 행 상세의 "N번째 행" 과 행 범위는 전체 기준 번호다. 복사는 지금 보이는 페이지만.
- 표 셀은 한 줄 미리보기 (줄바꿈은 `⏎`, 200자 초과 시 `…`). NULL 은 흐리게 `NULL`.

### 복사 · 빠른 필터
- 행을 고르고 `Ctrl+C` → TSV 로 복사 (엑셀에 바로 붙여넣기).
- 우클릭 → **CSV · INSERT · JSON · Markdown · IN 목록**으로 복사.
- **빠른 필터**: 결과 위 검색칸에 입력하면 받아 온 행 중 모든 단어가 어느 칸에든 들어 있는 행만 보인다 (대소문자 무시, NULL 은 `null` 로 찾음, 서버에 다시 묻지 않음).

### 내보내기
- 하단 **내보내기** → **내보내기 설정 창**(형식 카드 6개 · 범위 · 형식별 옵션) → **저장 위치 선택…** → 저장 창 (파일 이름 `테이블명_날짜시각.확장자`, 날짜시각은 **한국 표준시(KST)** 기준 `yyyyMMdd_HHmmss`, 마지막에 고른 형식을 기억):
  - **형식**: CSV / TSV / **Excel (.xlsx)** / JSON / SQL INSERT / Markdown
    - CSV·TSV: 엑셀 호환 UTF-8 BOM 선택 (기본 켬), 줄바꿈 CRLF. TSV 는 값 안의 탭·줄바꿈을 공백으로.
    - Excel: 머리글 굵게·고정, 숫자로 바꿔도 값이 그대로인 것만 숫자 셀(앞자리 0, 16자리 이상, 지수 표기는 문자). 시트 최대 1,048,575행 — 넘으면 앞까지만 저장하고 경고.
    - JSON: 행마다 `{컬럼: 값}` 객체, NULL 은 `null`, 같은 이름 컬럼은 `_2` 를 붙인다.
    - SQL INSERT: 대상 테이블 이름 입력, 100행씩 한 문장, DB 별 인용 부호, 값은 문자열 리터럴.
    - Markdown: Confluence · Jira 붙여넣기용 표 (`|` 와 줄바꿈 이스케이프).
  - **범위**: **쿼리 전체 결과** / **지금 보이는 행만**. 결과가 한 페이지뿐이면 보이는 행 = 전체.
    - 전체 결과는 **화면 페이지가 아니라 쿼리의 전체 데이터**를 **5,000행씩 나눠 다시 조회**하며 파일에 바로 쓴다 (메모리에 전부 올리지 않음).
    - 시작 전에 `COUNT(*)` 로 전체 행 수를 확인 → 결과 아래 줄에 `n / 전체행` 진행률과 **취소**(쓰던 파일 삭제).
    - 페이지 사이에 행이 빠지거나 겹치지 않도록: 화면 정렬(서버 정렬)이나 SQL 의 ORDER BY 가 있으면 그대로, 없으면 결과에 있는 **단일 컬럼 기본 키로 정렬**. 둘 다 없으면 저장 창과 상태창에 경고.
    - 끝나면 "전체 데이터 N행 (COUNT 와 일치)" 또는 개수가 다르면 경고를 상태창·로그에 남긴다.

## 9. 실행 계획 (EXPLAIN)

- **실행 계획** 버튼 또는 `Ctrl+Shift+Enter`: 커서 구문 앞에 `EXPLAIN` 을 붙여 실행한다 (SQL Server 는 `SET SHOWPLAN_ALL ON`).
- 결과 위에 **주의사항 요약** (MySQL 예):

| 조건 | 메시지 |
|---|---|
| `type = ALL` | 풀 테이블 스캔 (예상 행 수) — 인덱스 확인 |
| `type = index` | 인덱스 풀 스캔 |
| `possible_keys` 있는데 `key` 없음 | 사용 가능한 인덱스를 쓰지 않음 |
| `Extra` 에 `Using filesort` | ORDER BY 인덱스 검토 |
| `Extra` 에 `Using temporary` | GROUP BY / DISTINCT 검토 |

- PostgreSQL 은 Seq Scan · 디스크 정렬 · 큰 Nested Loop, SQL Server 는 Table/Clustered Index Scan · Sort · Key Lookup 을 짚는다.
- MySQL 8.0.16 이상이면 `EXPLAIN FORMAT=TREE` 결과를 **트리로 보기** 스위치로 볼 수 있다.
- 실행 계획 결과와 주의사항은 상태창에도 남는다. 결과 위의 **AI 로 튜닝하기** 버튼으로 [20. 쿼리 튜닝](#20-쿼리-튜닝-로컬-ollama)을 바로 시작한다.

## 10. 테이블 수정 (ALTER)

테이블 우클릭 → **테이블 수정 (ALTER)…**

- 화면 구성 (DataGrip Modify 와 비슷): 왼쪽 트리(테이블 > columns / keys / indexes / foreign keys) + 도구(+ − 복제 ↑ ↓), 오른쪽 고른 항목의 속성, 아래 미리보기.
- **컬럼**: 이름 / 코멘트 / 데이터 타입(자주 쓰는 타입 메뉴) / Not Null / Auto Increment / 기본 키 / 기본값 / On Update · 기타 Extra(MySQL). 추가, 삭제, 복제, 순서 이동.
  - 새 컬럼은 "새", 바뀐 항목은 주황 점, 지울 컬럼은 빨간 취소선(눌러서 되살리기).
- **인덱스**: 이름 / UNIQUE / 컬럼(순서대로 추가·위로·빼기). PRIMARY 는 컬럼만 바꿀 수 있다. 외래 키는 보기만.
- **테이블 코멘트** 편집.
- 아래 **미리보기 SQL** 이 실시간으로 바뀐다. MySQL 은 하나의 `ALTER TABLE` 문으로 만든다 (PostgreSQL · SQL Server 는 각 DB 문법으로).

| 변경 | 생성되는 절 (MySQL) |
|---|---|
| 인덱스 삭제 / 변경 | `DROP INDEX` (변경은 DROP 후 ADD) |
| 컬럼 삭제 | `DROP COLUMN` |
| 컬럼 이름 변경 | `CHANGE COLUMN old new …` |
| 컬럼 속성 변경 | `MODIFY COLUMN …` |
| 컬럼 추가 | `ADD COLUMN … AFTER 앞컬럼` (맨 앞이면 `FIRST`) |
| 인덱스 추가 | `ADD [UNIQUE] INDEX` / `ADD PRIMARY KEY` |
| 코멘트 | `COMMENT = '…'` |

- 검증: 빈 이름/타입, 중복 컬럼명, 인덱스의 없는 컬럼 → 미리보기에 빨간 오류, 실행 불가.
- 버튼
  - **쿼리 탭으로 열기**: 실행하지 않고 SQL 만 새 탭에 연다.
  - **실행…**: 확인창(접속명/DB 표시, "컬럼 삭제는 되돌릴 수 없음") 후 실행 → 성공 시 스키마 자동 새로고침, 상태창 기록.
  - 읽기전용 접속이면 실행 버튼 비활성.

> 컬럼 순서 이동만 한 경우(이름/속성 변경 없음)는 아직 ALTER 를 만들지 않는다.

## 11. 인덱스 보기

- 사이드바: 테이블 > **인덱스 N** 폴더에 인덱스 이름, 컬럼 순서, UQ/PK 표시.
- 인덱스 폴더 또는 테이블 우클릭 → **인덱스 상세 보기**: 인덱스 상세(MySQL `SHOW INDEX FROM` 의 카디널리티, Seq, Null, Index_type 등 / PostgreSQL 사용 횟수·크기 / SQL Server `sp_helpindex`)를 새 탭에.

## 12. 뷰 / 프로시저 / 함수 / 트리거

- 사이드바에 종류별 섹션으로 표시 (있을 때만).
- 더블클릭 또는 우클릭 → **정의 보기**: 정의 본문을 **새 탭 편집기에 전체 텍스트로** 연다.
- 뷰: 데이터 보기(SELECT). 프로시저: **CALL 문 만들기** (SQL Server 는 `EXEC`).

## 13. 스키마 비교

- 상단 모드 **스키마 비교** (보기 > 스키마 비교). 기준 접속/DB → 대상 접속/DB 를 골라 **비교**.
  - 접속 선택 목록: [DB 아이콘] 이름 · 환경 (예: `회원 DB · 운영`), 그룹이 있으면 그룹별로 묶는다. 고른 접속 옆에 사이드바와 같은 색 환경 표시.
- 결과: 일치 테이블 수 / 다름 / 누락, "대상에만 있는 항목" 체크로 참고 항목 표시.

| 종류 | 보정 SQL |
|---|---|
| 테이블 없음 | 기준 DB 의 CREATE 문 |
| 컬럼 없음 | `ADD COLUMN … AFTER` |
| 컬럼 다름 (타입/NULL/기본값/Extra/코멘트) | `MODIFY COLUMN` |
| 인덱스 없음 / 다름 | `ADD INDEX` / `DROP INDEX, ADD INDEX` |
| 대상에만 있음 | 없음 (참고용, **DROP 은 만들지 않음**) |

- **자동 실행하지 않는다.** 전체 SQL 복사 또는 쿼리 탭으로 열어 검토 후 실행.
- Redis 접속을 보고 있을 때는 비활성 (비교 대상 목록에도 Redis 제외).

## 14. 상태창 (로그)

- 창 하단 **상태 표시줄**: 마지막 이벤트 한 줄, 오류 건수, 상태창 열기 버튼 (`Ctrl+Shift+L`).
- **상태창**: 시간 · 종류(접속/쿼리/스키마/비교/앱) · 메시지 목록, 오른쪽에 상세.
  - 상세: 💡 해결 방법, 실행한 SQL, 원본 오류.
  - **오류가 나면 자동으로 열리고** 해당 항목이 선택된다.
  - 오류만 보기, 항목 복사, 전체 복사, 지우기, 로그 폴더 열기(탐색기). 화면에는 최대 1,000건 (앱 종료 시 사라짐).
- **감사 로그 파일** (설정 > 일반 > 로그 > "로그 파일 남기기", 기본 켜짐, **보관 기간**: 영구(기본) / 3개월 / 6개월 / 1년 — 지난 파일은 자동 삭제, 최소 90일): 나중에 **누가 · 언제 · 어느 DB 에 · 무엇을 했는지** 분석하는 용도. 상태창(화면)은 자세히, 파일은 **한 줄 = 한 행위**로 짧게.
  - 무결성: 줄마다 무결성 값과 이 PC 기기 키 서명이 마지막 두 칸에 붙는다 (날짜 파일끼리도 연결). 기기 키는 **TPM** 에 만들어 꺼낼 수 없고, TPM 이 없거나 쓸 수 없는 PC 에서는 **DPAPI 로 잠근 키**(지금 사용자 계정 · 이 PC 에서만 풀림)를 쓴다.
  - 위치: `%LOCALAPPDATA%\GodDB\Logs\goddb-audit-YYYY-MM-DD.tsv` (파일 권한: **지금 사용자만** 읽고 쓸 수 있게 ACL 설정, 기본 **영구 보관**).
  - 형식: **탭으로 나눈 6칸** (엑셀로 바로 열어 필터·정렬). 첫 줄 머리글, UTF-8 BOM.

    | 시각 | 사용자@PC | 구분 | 대상 | 결과 | 내용 |
    |---|---|---|---|---|---|
    | 2026-11-13 14:46:25.398 | kim@DESKTOP-01 | 조회 | dev/shop | 1행 · 3ms | SELECT * FROM `tb_member` |
    | 2026-11-13 14:50:02.110 | kim@DESKTOP-01 | 수정 | dev/shop | 결과 편집 1/2 (한 트랜잭션) | UPDATE `tb_member` SET … WHERE … |
    | 2026-11-13 14:51:10.004 | kim@DESKTOP-01 | 삭제 | redis_dev db0 | 키 삭제 · 21ms | DEL LOGIN_FAIL:kim |
    | 2026-11-13 14:52:00.000 | kim@DESKTOP-01 | AI | dev/shop | 튜닝 완료 · 17초 · qwen3:30b | |

  - **구분**: 앱시작 · 접속 · 접속해제 · 조회 · 추가 · 수정 · 삭제 · 구조변경 · 권한 · 실행 · 내보내기 · 비교 · AI · 설정
    - SQL 은 첫 키워드로 자동 분류 (SELECT/SHOW → 조회, INSERT → 추가, UPDATE/REPLACE/MERGE → 수정, DELETE/TRUNCATE → 삭제, CREATE/ALTER/DROP/RENAME → 구조변경, GRANT/REVOKE → 권한, 그 밖 → 실행). Redis 는 명령으로 (GET/SCAN → 조회, SET/EXPIRE → 수정, DEL/FLUSHDB → 삭제).
    - 여러 문장 스크립트, 결과 편집(한 트랜잭션)은 **문장마다 한 줄**.
    - 실패해도 같은 구분으로 남고 결과 칸이 `실패: 사유`.
  - **대상**: `접속이름/DB` (Redis 는 `접속이름 db번호`). **내용**: 실행한 SQL·명령을 한 줄로 편 것 (2만 자 넘으면 자름).
  - **앱시작** 줄: 앱 버전, 계정, 컴퓨터 이름, 호스트 이름, Windows 버전, 이 PC 의 IP 전체(어댑터, VPN 여부).
  - **접속** 줄: 그 순간 이 PC 에서 나가는 IP 와 경로 (`client 10.0.0.x → ssh bastion:22 → db:3306`). 외부 서비스에 묻지 않으므로 공인 IP 는 남기지 않는다.
  - **AI** 는 요약 한 줄만 (`튜닝 완료 · 17초 · 모델`, `AI 어시스턴트 답변 · 9초 · 모델`). 질문·프롬프트(테이블 구조·실행 계획)·답변 내용은 파일에 남기지 않는다.
  - 남지 않는 것: 조회 결과 행, 화면 이동(페이지 넘김·정렬·DDL 보기·다이어그램 열기), Redis 자동 새로고침. (단, 실행한 SQL 문장 안에 쓴 값은 그대로 남는다)
- **문제 보고** (도움말 > 문제 보고…, 상태창의 🐞 버튼): 제목 · DB 종류 · 재현 방법 · 기대/실제를 쓰고, 버전 · Windows 버전 · CPU 종류(x64 등), **최근 오류 20건**, **크래시 요약**(최근 3개)을 함께 담아 **GitHub(`zio0911/god_db_win`) 버그 신고 화면을 미리 채워 브라우저로 연다** (서버 없음, GitHub 로그인 필요).
  - 크래시: 앱이 처리하지 못한 오류로 꺼지면 `%LOCALAPPDATA%\GodDB\Crashes` 에 기록을 남기고, 문제 보고가 그 요약(오류 종류 · 메시지 · 스택 앞부분, 파일 경로 제외)을 담는다.
  - 호스트 이름 · IP · 이메일 · 계정 · 사용자 폴더 경로(`C:\Users\이름`)는 자동으로 가리고(`<host>`, `<ip>`, `~` …), 보내기 전에 내용을 직접 고칠 수 있다. [복사] 로 클립보드에 담을 수도 있다.
- 오류 번역 예시

| 연결 시간 초과 | 연결 시간 초과 + VPN/보안 그룹 확인 |

## 20. 쿼리 튜닝 (로컬 Ollama)

### 설정 > AI
- AI 어시스턴트 사용 · 쿼리 튜닝 사용 각각 켜기/끄기 (끄면 버튼이 사라짐), Ollama 주소 (기본 `http://localhost:11434`).
- 상태 자동 확인: 실행 중(모델 N개) / 설치됐지만 꺼져 있음(**Ollama 실행** 버튼) / 설치 안 됨(**Ollama 내려받기 (ollama.com)** 링크).
  - 설치 확인: Ollama Windows 설치 프로그램이 까는 `%LOCALAPPDATA%\Programs\Ollama\ollama.exe`, 없으면 PATH 의 `ollama.exe`.
- 모델: 설치된 모델 중 선택 (기본은 첫 번째). 추천 `qwen2.5-coder:14b`, `qwen2.5-coder:32b`, `qwen3:30b` (받는 명령 `ollama pull …` 복사 버튼).
- 이 PC 밖의 주소를 넣으면 "스키마가 그 서버로 전송된다" 경고.

### 쿼리 탭 > AI 튜닝 (`Ctrl+Alt+T`)
- 툴바의 보라색 **AI 튜닝** 버튼, 또는 실행 계획 결과 위의 **AI 로 튜닝하기** 버튼.
1. 선택 영역 또는 커서가 있는 문장을 대상으로
2. 자동으로 모으는 정보: DB 종류·버전, 쿼리에 나온 테이블의 DDL(컬럼·인덱스), 예상 행 수(통계), 실행 계획 + 자동 주의사항
3. 로컬 Ollama 에 스트리밍 요청 → "생각하는 중 / 답변 쓰는 중" 진행 표시
4. 결과 창: **요약 · 실행 계획 주의사항 전/후 비교 · 개선 SQL · 추천 인덱스 · 설명**
   - 개선 SQL 은 EXPLAIN 만 다시 떠서 비교 (실행하지 않음). 추천 인덱스는 만들지 않으므로 '후' 계획에 반영되지 않는다.
   - 버튼: 복사 / 편집기에 넣기 / 새 탭으로. **자동 실행·인덱스 생성 없음.**
   - "Ollama 에 보낸 정보 보기" 로 실제 보낸 내용을 그대로 확인할 수 있다.
- 보내지 않는 것: 실제 데이터 행, 비밀번호, 접속 정보.
- 답변 언어는 앱 언어(한국어/영어)를 따른다.
- 일부 모델(qwen3 등)은 `think:false` 를 주면 생각이 본문에 섞여서, 옵션을 보내지 않고 생각/본문을 분리해 받는다.

## 21. 결과 데이터 편집

- **편집 가능 조건**: 테이블 하나만 조회한 SELECT (JOIN·GROUP BY·DISTINCT·UNION·HAVING·서브쿼리 없음), 테이블에 기본 키가 있고 결과에 기본 키 컬럼이 포함, 읽기전용 접속이 아님. 아니면 결과 위에 "편집 불가: 이유" 표시.
- 결과 위 편집 막대: `행 추가` · `선택 행 삭제`(다시 누르면 해제) · `변경 N건` · `되돌리기` · `적용…`
- 행 **더블클릭** → 오른쪽 행 편집 패널. 행 **우클릭** → 이 행 편집 / 행 추가 / 선택 행 삭제(삭제 표시 해제) / 행 복사.
- 행을 고르면 오른쪽 **행 편집** 패널에서 값 수정, NULL 지정, (새 행) DB 기본값 사용. 기본 키 컬럼은 🔑 표시.
- 표시: 바뀐 셀 주황 굵게, 새 행 초록, 삭제 표시 빨간 취소선, 새 행의 입력 안 한 칸 `(기본값)`.
- **적용…** → 실행할 DELETE / UPDATE / INSERT 미리보기 → **한 트랜잭션**으로 실행, 하나라도 실패하면 전부 ROLLBACK → 성공하면 같은 페이지를 다시 읽는다.
  - WHERE 는 기본 키로만 만든다. 값은 문자열 리터럴로 넣고 DB 가 컬럼 타입으로 변환한다.
  - 바이너리 컬럼에 `0x…` 를 넣으면 바이너리로 저장 (MySQL `X'…'`, PostgreSQL `decode('…','hex')`, SQL Server `0x…`).
- 변경이 남아 있으면 페이지 이동이 막힌다 (적용하거나 되돌린 뒤 이동). 적용하지 않은 편집을 버리게 되는 동작(탭 닫기, 다시 실행 등)은 먼저 확인한다.

### 바이너리 표시
- varbinary / binary / BLOB / bytea / image 는 DataGrip 처럼 **`0xCD01FF…` 16진수**로 보인다.
- SQL Server 드라이버(Microsoft.Data.SqlClient)는 표준 ANSI 세션 설정(`ANSI_PADDING`, `ANSI_NULLS`, `QUOTED_IDENTIFIER` 등 ON)이 기본이라 varbinary 값이 SSMS · DataGrip 과 같게 보인다.

## 22. 테이블 이름 변경 · 삭제 · 생성문 새로고침

- 테이블 우클릭 → **이름 변경…** : 새 이름 입력, 실행 SQL 미리보기 (MySQL `RENAME TABLE`, PostgreSQL `ALTER TABLE … RENAME TO`, SQL Server `sp_rename`). 열려 있던 그 테이블의 DDL 탭 이름도 바뀐다.
- 테이블 우클릭 → **삭제 (DROP)…** : 테이블 이름을 그대로 입력해야 삭제 버튼이 켜진다. 되돌릴 수 없음 경고.
- 읽기전용 접속에서는 두 메뉴가 꺼진다. 성공하면 사이드바 스키마를 다시 읽는다.
- DDL·정의 탭(CREATE 문 보기, 뷰/프로시저/함수/트리거 정의)의 툴바에 **생성문 새로고침** 버튼: DB 에서 다시 읽어 편집기 내용을 바꾼다 (테이블은 스키마도 새로 읽음).

### 헤더 클릭 정렬
- 결과 표 헤더를 누르면 오름차순, 다시 누르면 내림차순 (헤더에 화살표).
- **쿼리를 다시 실행해서 정렬한다**: `SELECT * FROM (원래 쿼리) AS goddb_sort ORDER BY 컬럼 ASC|DESC` → 첫 페이지부터. 페이지를 넘겨도 정렬 유지.
  - 원래 쿼리의 맨 바깥 ORDER BY 는 뺀다 (단 LIMIT/TOP/OFFSET 이 있으면 결과 집합이 바뀌지 않게 그대로 둔다).
  - SHOW 처럼 감쌀 수 없는 결과만 받아 온 행을 앱에서 정렬 (NULL 먼저, 숫자는 숫자 크기).
- 편집 중인 변경이 있으면 정렬 전에 적용하거나 되돌려야 한다. 실행한 정렬 SQL 은 상태창에 남는다.

### 결과 영역 hover
- 마우스가 올라간 **행을 강조**한다.
- 페이지 이동·복사·전체 행 수·결과 탭·행 상세 버튼: 올리면 강조색 배경과 테두리, 누르면 더 진해진다.
- 페이지 이동/행 수 세기 중에는 결과 표는 그대로 두고 페이지 바에만 로딩 표시.

## 23. ER 다이어그램

- 여는 방법
  - 테이블 우클릭 → **다이어그램 보기**: 그 테이블 + 외래 키(또는 추정 관계)로 바로 이어진 테이블. 중심 테이블은 보라색.
  - 사이드바에서 테이블을 **Ctrl/Shift 클릭으로 여러 개 선택** → 머리글의 다이어그램 버튼, 또는 고른 테이블 중 하나를 우클릭 → "다이어그램 보기 (선택한 N개)":
    고른 테이블은 **관계가 없어도 모두 따로** 보이고(보라색), 관계(외래 키·추정)가 있으면 **이어진 테이블도 함께**(파란색) 그린다.
  - 아무것도 고르지 않고 머리글의 다이어그램 버튼 → **스키마 전체** (최대 200개 테이블).
- **이름 표시**: 물리명(실제 이름) / 논리명(코멘트 첫 줄) / 둘 다. 코멘트가 없으면 물리명을 흐리게(기울여) 보여준다. 선택은 기억된다.
- **관계 추정** (기본 켬): 외래 키 제약이 없는 DB 를 위해, 컬럼 이름이 다른 테이블의 **단일 컬럼 기본 키 이름과 같으면** 관계로 보고 **점선**으로 그린다 (DataGrip 의 가상 외래 키와 비슷).
  - 자기 기본 키, 이미 진짜 외래 키가 있는 컬럼, 흔한 이름(id, seq, no, code …)은 제외.
  - 같은 기본 키 이름을 가진 테이블이 여럿이면 테이블 이름이 가장 비슷한 하나만 (애매하면 그리지 않음).
  - 진짜 외래 키는 실선, 추정은 점선. 툴바 체크박스로 끌 수 있다.
- 별도 창으로 열리고 여러 개를 동시에 띄울 수 있다. 연 순간의 스키마를 그린다 (구조가 바뀌면 다시 열기).
- 테이블 카드: 이름, 컬럼(🔑 기본 키, 🔗 외래 키 컬럼, 타입). 컬럼 24개 넘으면 "… N개 더".
- 관계선: 외래 키 컬럼 → 참조 컬럼. 자식 쪽 까마귀발, 부모 쪽 막대. 자기 참조는 고리 모양.
- 배치: 참조되는 테이블(부모)을 왼쪽, 참조하는 테이블(자식)을 오른쪽 열에. 관계 없는 테이블은 아래에 격자.
- 열 때 모든 테이블이 한 화면에 보이도록 자동으로 배율을 맞춘다 (툴바 "화면에 맞추기"로 다시).
- 조작: 카드 끌어서 이동, 마우스를 올리면 그 테이블의 관계만 강조, 확대/축소(30~200%), 자동 정렬, **PNG 저장**(2배 해상도).
- 외래 키 읽기 (같은 DB/스키마 안의 참조만): MySQL `information_schema.KEY_COLUMN_USAGE`, PostgreSQL `pg_constraint`, SQL Server `sys.foreign_keys`. 여러 컬럼 외래 키 지원.
- **AI 분석** (툴바 "AI 분석" → 오른쪽 패널, 너비 조절 가능): 설정 > AI 의 로컬 Ollama 와 모델을 쓴다.
  - "관계 분석 시작": 도메인·핵심 테이블, 관계별 카디널리티, FK 가 빠진 관계·인덱스 없는 FK 컬럼, 모델링 문제, 대표 JOIN 쿼리
  - 채팅: 이어서 자유롭게 질문 (Enter 로 보내기, 예시 질문 버튼). 대화 맥락을 기억하고, 답변 복사 / 답변의 SQL 을 쿼리 편집기에 넣기
  - **대화 기록**: 다이어그램(접속 · DB · 테이블 묶음)마다 저장해서 다시 열면 마지막 대화가 그대로 보인다 (분석이 오래 걸리므로). 🗨️+ "새 대화", 🕘 이전 대화 목록에서 열기/삭제, "이 다이어그램의 대화 모두 삭제"(확인). 90일 지난 대화는 자동 삭제. 위치 `%APPDATA%\GodDB\diagram-chats\` (지금 사용자만 읽을 수 있음)
  - 보내는 것: 다이어그램에 있는 테이블의 컬럼·타입·PK·NULL·코멘트·인덱스, 선언된 FK, 추정 관계. **데이터 행은 보내지 않는다.** 스키마가 크면 컬럼 목록을 줄여서 보낸다 (약 4만 자).

## 24. 접속 정보 내보내기 · 가져오기

- 사이드바 **접속** 목록 아래 ⇅ 메뉴 → "접속 정보 내보내기…" / "접속 정보 가져오기…"
- **내보내기**: 내보낼 접속을 체크 → 저장 위치 선택 → `goddb-connections-YYYYMMDD.json` (지금 사용자만 읽을 수 있게 저장)
  - 기본은 비밀번호를 넣지 않는다. 받는 쪽에서 처음 연결할 때 입력.
  - "비밀번호 포함" 을 켜면 정한 암호(8자 이상)로 잠근다: PBKDF2-SHA256(20만 회) → AES-256-GCM. 암호는 파일에 없으니 따로 전달.
  - SSH 개인키 파일은 넣지 않고 경로만 넣는다.
  - **macOS 판 GodDB 와 같은 파일 형식**이라 Mac ↔ Windows 로 주고받을 수 있다 (SSH 키 경로 · Windows 인증 설정은 받는 쪽에서 확인).
- **가져오기**: 파일 선택 → 목록에서 가져올 접속 체크
  - 새 접속은 "새로 추가"(기본 체크), 같은 접속(같은 id)이 이미 있으면 "이미 있음 → 덮어씀"(기본 해제)
  - 이름이 다른 접속과 겹치면 ` (2)` 를 붙인다.
  - 비밀번호가 들어 있으면 암호를 넣어 함께 가져온다 (비우면 비밀번호 없이). 접속의 "비밀번호 저장" 설정에 따라 자격 증명 관리자 또는 실행 중에만 보관.
- 내보내기·가져오기는 상태창과 로그 파일에 남는다.
- **DataGrip 붙여넣기**: DataGrip 에서 데이터 소스를 고르고 `Ctrl+C` → GodDB 사이드바에서 `Ctrl+V` (또는 ⇅ 메뉴 > "DataGrip 접속 정보 붙여넣기")
  - `jdbc-url` 에서 종류·호스트·포트·DB·TLS 옵션, `user-name`, 이름, uuid(다시 붙여넣으면 같은 접속으로 인식)를 읽는다. 여러 개를 한 번에 붙여넣어도 된다.
  - 지원: MySQL/MariaDB/Aurora, PostgreSQL, SQL Server(`;database=`, `\인스턴스`), Redis. 그 외 DB 는 "지원하지 않음"으로 알려준다.
  - 드라이버 래퍼 주소도 읽는다: `jdbc:aws-wrapper:mysql://`(AWS Advanced JDBC Wrapper), `jdbc:p6spy:`, `jdbc:log4jdbc:`, `jdbc:mysql:replication://`·`loadbalance://`(첫 호스트 사용), jTDS
  - 비밀번호는 DataGrip 이 따로 보관해서 들어 있지 않다 → 처음 연결할 때 입력.
  - SSH 터널을 쓰는 데이터 소스는 SSH 설정 id 만 들어 있다 → SSH 를 켠 상태로 가져오고 바스티온 정보는 접속 편집에서 넣으라고 안내.

## 25. Redis

- 접속 종류 **Redis** (기본 포트 6379). 비밀번호(AUTH), ACL 사용자(선택), DB 번호(0~15), TLS(ElastiCache 전송 중 암호화), SSH 터널, 읽기전용 지원.
- 드라이버: RESP2 프로토콜을 직접 구현 (추가 라이브러리 없음). 명령은 파이프라인 순서대로 응답을 받는다. 연결 과정(AUTH · SELECT · INFO · CLUSTER SLOTS · 센티널 조회 · TLS)에서 서버가 10초 안에 응답하지 않으면 연결을 끊고 "Redis 서버가 10초 안에 응답하지 않았어요…" 로 알려준다 (콘솔 · BLPOP 같은 차단 명령은 제한 없음).
- **사이드바**: DB 선택(키 개수 표시), 키 목록. `SCAN` 으로 1,000개씩 가져온다 (`KEYS` 는 운영 서버를 멈출 수 있어 쓰지 않음). 아래 검색칸에 패턴(`user:*`) + 타입 필터.
  - **트리 보기(기본)**: 키를 구분자(기본 `:`, `/` `.` `_` `-` `|` 선택)로 나눠 폴더처럼 표시 (`user:1001:name` → user › 1001 › name). 폴더마다 하위 키 개수, 숫자는 숫자 순서. 폴더 우클릭 "이 폴더만 검색". 트리/목록 전환 버튼.
  - 키마다 **타입 배지(S/H/L/St/Z/X)와 남은 TTL**(45s·12m·3h·2d, 1분 미만 주황)을 미리 표시 → 누르면 값이 열린다. 화면에 보이는 키만 TYPE·PTTL 을 파이프라인으로 묶어 조회.
  - 새로고침 + **자동 새로고침**(켜기/끄기, 간격 초 입력 1~3600, 기본 5초): 키 목록·TTL·열린 값을 다시 읽고 펼친 폴더와 선택은 유지. 연결이 끊기면 자동으로 멈춤.
- Redis 접속을 보고 있을 때는 **스키마 비교 비활성** (비교 대상 목록에도 Redis 제외).
- **키 탭**: 타입·TTL·원소 수·메모리(MEMORY USAGE)·인코딩 표시, 새로고침 / TTL 설정·해제 / 이름 변경 / 삭제(확인)
  - string: 편집 후 저장(`SET … KEEPTTL`), JSON 이면 보기 좋게 펼치기
  - hash: 필드·값 표, HSET / HDEL / list: LPUSH·RPUSH·LSET·LREM, 500개씩 더 보기 / set: SADD·SREM / zset: 점수 높은 순, ZADD·ZREM / stream: 최근 200개
  - 새 키 만들기 (타입별, 만료 지정)
- **Workbench** (RedisInsight 의 Workbench 와 같은 방식): 아래 여러 줄 편집기에 명령을 한 줄에 하나씩 쓰고 **▶ 실행(`Ctrl+Enter`)** → 위에서부터 차례로 실행, 결과는 위에 redis-cli 모양으로 쌓인다. 선택 영역이 있으면 그 줄만 실행. `//`·`#` 주석 줄은 건너뜀. 커서 줄 명령 인자 안내, 이전 명령 넣기, 결과에서 "편집기에 다시 넣기". 편집기 내용은 접속마다 기억. `FLUSHALL`·`FLUSHDB`·`KEYS`·`CONFIG SET`·`SHUTDOWN` 등이 섞여 있으면 실행 전에 한 번 더 확인 (설정 > 일반 > 안전 에서 끌 수 있음). `SELECT` 하면 DB 표시도 바뀐다.
- **Pub/Sub**: 채널/패턴 구독(쉼표로 여러 개, `*`·`?` 가 있으면 PSUBSCRIBE), 들어오는 메시지 실시간 표 (시각·채널·패턴·메시지), 거르기·일시 정지·지우기, PUBLISH 보내기, 활성 채널과 구독자 수. 구독은 별도 연결을 쓴다.
- **Streams**: 스트림 목록 → 항목(최신순 200개씩, ID 시각 표시), `XADD`(`field=value …`), `XDEL`, **실시간 보기**(별도 연결에서 `XREAD BLOCK`), 소비자 그룹(소비자 수·대기·Lag·마지막 전달 ID), 그룹 만들기(`$`/`0`)·SETID 0·DESTROY, 소비자별 대기, PEL(ID·소비자·유휴·전달 횟수) → 선택해서 `XACK`.
- **서버 정보**: `INFO` 섹션별 표 + 주요 값(버전, 메모리, 클라이언트, 초당 명령 수 …), 찾기.
- 읽기전용 접속: 조회 명령만 허용 (GET/HGETALL/SCAN/XRANGE/XINFO/INFO/CONFIG GET … 허용 목록 방식). XREADGROUP·PUBLISH 도 막는다.
- 모든 쓰기 명령과 콘솔 명령은 상태창과 로그 파일에 남는다.
- **Redis Cluster**: 접속 편집 > 방식 "Cluster" (또는 "단일"로 붙어도 서버가 Cluster 면 자동 전환). 노드 하나(또는 ElastiCache 구성 엔드포인트)만 적으면 `CLUSTER SLOTS` 로 전체 노드·슬롯을 찾는다.
  - 명령은 키의 슬롯(CRC16, `{태그}` 지원)에 맞는 마스터로 보내고, `MOVED`(슬롯 표 다시 읽기)·`ASK`(ASKING 후 재전송) 는 자동으로 따라간다 → **노드 IP 로 다시 접속할 필요 없음**.
  - 키 목록(SCAN)·키 개수(DBSIZE)는 모든 마스터를 차례로 훑어 합친다. 타입·TTL 조회도 노드별로 묶어 파이프라인.
  - DB 는 0 만 (SELECT 는 안내). 서버 정보 탭에서 노드를 골라 노드별 INFO. Pub/Sub 은 아무 노드, Streams 실시간 보기는 키가 있는 노드.
  - SSH 바스티온을 쓰면 노드마다 터널을 자동으로 연다.
  - 상단에 "Cluster · 마스터 N개" 배지 (마우스를 올리면 노드 주소).
- **Redis Sentinel**: 방식 "Sentinel", 호스트 칸에 센티널 주소(쉼표로 여러 개, 기본 포트 26379), 마스터 이름(예: `mymaster`). `SENTINEL get-master-addr-by-name` 으로 현재 마스터를 찾아 접속 (센티널 인증이 필요하면 같은 비밀번호로 다시 시도). 장애 조치 후에는 다시 연결하면 새 마스터로 붙는다.
- 아직 안 되는 것: 복제본(replica) 읽기, RESP3, 모듈(JSON 등)은 Workbench 로만.

## 26. INSERT 컬럼 힌트

- `INSERT INTO t (a, b) VALUES ('x', 'y')` 처럼 쓰면 편집기에서 각 값 앞에 **회색으로 컬럼 이름**(`a`, `b`)이 보인다. 컬럼 목록을 안 쓰면 사이드바 스키마의 컬럼 순서로 표시.
- 여러 행(`VALUES (…), (…)`), 문자열 안 쉼표·괄호, 함수 호출, 주석, 입력 중(괄호가 안 닫힘)도 처리.
- 화면에만 그리므로 **편집기 글자와 실행하는 SQL 은 바뀌지 않는다** (복사해도 글자만 복사).
- 항상 켜져 있다 (Mac 과 같이 설정에서 끄는 옵션은 없다).

## 27. 모델링 (MySQL Workbench 모델과 비슷)

- 상단 모드 **모델링** (쿼리 / 스키마 비교 / 모델링, 보기 > 모델링). 접속 없이도 쓸 수 있다.
- **논리 설계**: 논리명으로 테이블·컬럼을 만들고, 도구 막대의 관계 도구(1:N 비식별, 1:N 식별, 1:1)로 부모 → 자식 테이블을 차례로 누르면 관계가 생긴다. 부모 기본 키가 자식에 FK 컬럼으로 복사된다 (`id` 같은 흔한 이름은 `부모테이블_id`).
- **다이어그램**: IE 표기 (까마귀발 = N, 막대 = 1, 원 = 선택), 식별 관계는 실선 · 비식별은 점선. 카드 끌어 옮기기, 자동 정렬, 확대/축소, 카드 색, PNG 저장. 논리명 / 물리명 / 둘 다 보기.
- **물리 설계**: 아래 편집기에서 컬럼마다 논리명·물리명·타입(자주 쓰는 타입 메뉴)·PK·NN·AI·UQ·기본값·설명, 여러 컬럼 인덱스, 관계 속성(카디널리티, 식별, 선택, FK 이름, ON DELETE/UPDATE, FK 제약 생성 여부).
- **모델 검사**: 물리명 없음·중복·영문 외 글자, 타입 없음, 기본 키 없음. 오류가 있으면 SQL 추출을 막는다.
- **SQL 추출 (Forward Engineering)**: MySQL / PostgreSQL / SQL Server 문법으로 CREATE TABLE + FK(ALTER TABLE 로 마지막에). 코멘트는 `논리명` + 줄바꿈 + `설명`. DROP 먼저 옵션, 복사 · .sql 저장 · 쿼리 탭으로 열기 (실행은 직접).
- **리버스 엔지니어링**: 연결된 DB 의 테이블을 골라 모델로. 코멘트 첫 줄 → 논리명, FK → 관계, 원하면 컬럼 이름으로 추정한 관계(FK 제약 없는 논리 관계).
- **DB와 비교 (Synchronize)**: 모델과 연결된 DB 를 비교해 DB 를 모델에 맞추는 ALTER SQL (DB 에만 있는 것은 지우지 않음).
- 자동 저장, 되돌리기(구조 변경), 복제, 이름 바꾸기, `.goddbmodel` 파일로 내보내기/가져오기. **macOS 판과 같은 파일 형식**이라 서로 열 수 있다.

## 28. AI 어시스턴트 (오른쪽 패널)

- 도구 막대 ✨ 버튼 또는 `Ctrl+Shift+I` (보기 > AI 어시스턴트). 로컬 Ollama (쿼리 튜닝과 같은 모델) 와 대화.
- **쿼리 모드**: 테이블 목록 + 질문에 나온 테이블(물리명 또는 논리명) · 사이드바에서 고른 테이블 · 지금 탭 테이블의 구조·코멘트·인덱스·FK, 테이블 크기 통계(추정 행 수·용량), 자동 점검(기본 키 없음, 코멘트 없음, 인덱스 없는 FK, NULL 허용 FK, 중복 인덱스, 큰 테이블 등), 편집기 SQL·마지막 오류를 문맥으로 보낸다. 무엇을 보내는지 패널 위에 표시.
- **데이터 행은 보내지 않는다.** 데이터가 필요하면 실행할 SELECT 를 알려준다.
- **앱 사용법 질문**: 앱 정보(제작자·라이선스·저장소)와 지금 앱 상태(버전·모드·연결·선택 테이블·열린 모델), 이 기능 명세에서 질문과 관련된 절을 함께 보내 "리버스 엔지니어링 어떻게 해?" 같은 질문에도 답한다. 접속하지 않아도 된다.
- **모델링 모드**: 지금 모델을 문맥으로 검토. "물리명 추천" 답의 JSON 을 **물리명 적용 (빈 칸만)** 버튼으로 모델에 바로 넣는다.
- 자주 쓰는 질문 버튼, 답의 SQL 을 편집기에 넣기, 범위(접속·DB / 모델)별 대화 기록 90일 보관 · 새 대화 · 삭제(확인).
- 설정 > AI 에서 끄면 버튼과 패널이 사라진다.

## 29. 접속 그룹

- 접속 우클릭 > 그룹으로 이동 (기존 그룹 / 새 그룹… / 그룹에서 빼기), 접속 편집 창의 그룹 칸, 접속을 그룹 이름 위로 끌어 놓기.
- 그룹은 사이드바에서 접었다 펼 수 있고 (상태 기억), 연결된 접속 수를 보여준다. 그룹 우클릭으로 이름 바꾸기 · 그룹 풀기.
- 접속 내보내기/가져오기에 그룹도 함께 들어간다.

## 30. 시작 화면 · 자동 업데이트 · 새로운 기능

- **시작 화면**: 앱을 켜면 아이콘 · 버전 · 진행 막대 · 지금 하는 일이 보인다. 단계: 설정·접속 목록 → PC·네트워크 정보(감사 로그 앱시작 줄) → AI(Ollama) 확인(2.5초 제한) → 모델·대화 기록 정리 → 업데이트 확인. 느린 단계가 실패해도 앱은 열린다.
- **설치**: GitHub 릴리스(github.com/zio0911/god_db_win)의 `GodDB-win-Setup.exe` 를 실행하면 **사용자 폴더**(`%LOCALAPPDATA%` 아래)에 설치되고 시작 메뉴에 GodDB 가 생긴다. **관리자 권한이 필요 없다.** 설치하지 않고 쓰려면 `GodDB-win-Portable.zip` 을 풀어 `GodDB.exe` 를 실행한다.
  - 코드 서명: 지금 배포 파일은 코드 서명이 되어 있지 않아, 처음 실행할 때 Microsoft Defender SmartScreen 의 "Windows 의 PC 보호" 창이 뜰 수 있다. **추가 정보 → 실행** 을 누르면 된다. (서명 방식은 이후 릴리스에서 바뀔 수 있다)
- **자동 업데이트** (Velopack, **업데이트 서버 없음**): GitHub 릴리스에 올린 업데이트 파일을 읽는다.
  - 설정 > 업데이트: **자동 업데이트(받아서 설치)** / **확인하고 알림(기본)** / **수동(메뉴에서만)**
  - 도움말 > **업데이트 확인…** (설정 > 업데이트 > 지금 업데이트 확인…). 업데이트 창에 그 버전의 변경 내용이 보인다.
  - 자동 모드에서 새 버전을 받으면 지금 다시 시작할지 묻고, 나중에 하면 앱을 끌 때 설치된다. 설치하면 감사 로그에 `설정 | 업데이트 설치 1.0.0 → 1.1.0` 이 남는다.
  - 앱을 시작할 때와 하루에 한 번 확인한다 (수동이면 확인하지 않음).
- **새로운 기능** (도움말 > 새로운 기능): 이 문서의 변경 이력을 버전별로 보여준다. 새 버전을 처음 켜면 지난 버전 이후 바뀐 것을 강조해서 한 번 띄운다. **[AI 에게 물어보기]** 로 버전 사이 차이를 요약받는다.
- **AI 어시스턴트가 버전을 안다**: "1.0 이랑 1.1 뭐가 달라?", "이번 업데이트에서 뭐 바뀌었어?" 처럼 버전·업데이트를 물으면 변경 이력(최근 10개 버전)을 함께 보내 답한다.

## 17. 알려진 제약

- SQL Server: 세션 단위 읽기전용이 없어 앱 검사만 한다. 기본값 변경 시 기존 기본값 제약조건 삭제는 안내 주석으로만 만든다.
- SQL Server Windows 인증은 지금 Windows 에 로그인한 계정으로만 접속한다 (다른 Windows 계정을 골라 접속하는 기능은 없음).
- 비밀번호 방식 SSH 미지원 (키 파일 / ssh-agent 만).
- 서로 다른 종류의 DB 끼리 스키마 비교는 가능하지만 타입 이름 차이로 "다름"이 많이 나온다.
- 화면 자동 테스트는 화면 없이(headless) 도는 앱 상태 · 창 테스트만 있다. 실제 화면을 눌러 보는 자동 테스트는 없어서 화면 흐름은 수동으로 확인한다.

## 18. 변경 이력

### 1.3.7
- Windows 판 첫 릴리스: macOS 판 1.3.7 과 같은 기능 + **SQL Server Windows 통합 인증** (버전 번호는 macOS 판과 맞춘다 — 같은 번호면 같은 기능)
- 비밀번호는 **Windows 자격 증명 관리자**에 저장, 저장된 비밀번호 보기는 **Windows Hello**(지문 · 얼굴 · PIN) 또는 Windows 로그인 암호로 확인
- SSH 터널은 Windows 내장 OpenSSH(`ssh.exe`) 사용, SQL Server 명명된 인스턴스(`host\instance`) 접속
- 감사 로그 기기 키는 TPM (없으면 DPAPI 로 잠근 키), 로그는 `%LOCALAPPDATA%\GodDB\Logs`
- 설치: `Setup.exe`(사용자 폴더, 관리자 권한 불필요) 또는 포터블 zip, **Velopack 자동 업데이트**(GitHub 릴리스)
- 단축키는 Windows 표기 (`Ctrl+Enter` 커서 문장 실행, `Ctrl+Alt+Enter` 전체 실행, `Ctrl+T` 새 탭, `Ctrl+W` 탭 닫기 …), 메뉴는 창 안 메뉴 막대
- macOS 판 1.3.6 · 1.3.7 변경 포함: `Ctrl+Enter` 는 커서 문장만 + **전체 실행**, 끌어서 바꾼 경계 크기 기억 · **보기 > 레이아웃 초기화**, DB 공식 로고 아이콘 · 스키마 비교 접속 목록에 환경 표시, **설정 > 일반 > 안전 > 위험한 명령 실행 전 확인**, Redis 연결 10초 응답 제한, 좁은 창에서 페이지 크기 · 결과 아래 줄이 잘리지 않음
- 내보내기 파일 이름 시각은 한국 표준시(KST), CSV 가져오기는 UTF-8 이 아니면 CP949 로 읽음
